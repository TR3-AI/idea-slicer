# AGENTS.md — binding rules for any agent working in this repo

This repo runs **idea-slicer**: GitHub issues are the ideas, `maps/<slug>.md` files are the source of truth, the HTML pages are generated artifacts. Everything below is mandatory.

## Never hand-edit

- Any `*.html` containing the comment `generated by idea-slicer` — regenerated from issue bodies on every issue event; hand edits are wiped without warning.
- `pages.json` — rebuilt by `render.js` on every render run.
- Hand-written and safe to edit: `index.html`, `rulebook.html`, `nav.js`, `render.js`, `template.html`, `maps/*.md`.

## The rules

1. **Understand first.** Read the whole idea end to end before slicing. Never slice sentence-by-sentence.
2. **Operating flow first.** Every map starts with how the finished system runs, trigger to outcome. Structure follows the flow.
3. **Departments, not tasks.** A department owns a responsibility and runs in parallel. Shared state merges departments; a hard contract boundary splits them.
4. **Genuine modules only.** A module is a real building block (external adapter, stateful engine, non-trivial algorithm). One calculation or one config value is a feature, not a module.
5. **Mobile is the primary screen.** Bobby reads these pages on his phone. No visual change is done until verified at ~390px as well as desktop: no clipped labels, no off-screen content, no dead white space.
6. **Terse chat, rich page.** Chat replies carry only what changed; the page carries the full structure. ELI5 clarity, zero dumbing-down — technical terms stay, glossed in plain words on first use.
7. **Owner dependencies are explicit.** Anything only Bobby can supply (keys, accounts, decisions) is a blocking dependency, referenced by secret name — never stored raw.
8. **Facts are decision-grade and near-verbatim.** A fact earns its place only if a cold reader or agent would get the idea wrong without it — no restatements of the obvious. Each fact stays close to the source ruling's exact words and cites it (`[#k]` or `[raw log]`). Interpretation and plain-language explanation live in FAQs, never in a fact.
9. **Contradictions stop the line.** Every new thought is checked against the pinned facts and rules before it is sliced — thresholds, better/worse directions, gate order. A thought that conflicts is never silently merged: quote both sides, park the conflict in Unresolved (`<new> vs <existing> — which stands?`), wait for Bobby's ruling. The ruling cites both sources.
10. **A repository link is a valid input.** Pasted after the command, same as pasted text: the agent must actually clone and read the repo code (`gh`/`git` into a local work dir — never guesses from the URL) and build the slice — operating flow, departments, structure — from what the code actually does: user-visible surfaces first, then the machinery behind them. A repo input means `System: existing` with the four lists (already exists / being extended / being changed / new). Code says what exists; pasted documents say what was intended — disagreements get named. Unreadable repo (private, no access): stop and say so — never fabricate a slice from a URL. Done by the agent, enforced completely: an unread repo passed off as read is mumbo-jumbo, and mumbo-jumbo fails the run.
11. **Rules for rules (the meta-rule).** A new rule is not a rule until it is enforceable by any agent on any model. In the same turn it is decided: (1) written into EVERY synced copy — the skill's SKILL.md, the profile copies (5, him, moon — checksums must match), this AGENTS.md, and rulebook.html; (2) written as an enforceable instruction — imperative, specific, observable outcome — never a bare principle; (3) given a mechanical check where one can exist (a format the renderer parses, a grep-able page element); (4) verified active before the turn ends — profiles synced, repo pushed, live page greps pass. Models inherit rules only through these files; a rule in only some copies, or one no agent can check, does not exist.

12. **P-stack below governs every slice — and it is enforceable.** A slice output is only done when it was produced under these principles and skills; an output that ignores them fails the run. Copied like-for-like from pstack v0.14.8 (`github.com/cursor/plugins/tree/main/pstack`). Do NOT use `/poteto-mode Feature` here: slices stay capabilities — no tickets, no code. Feature Map is not "part two" of Idea Slicer — they are two different skills that work together: Feature Map takes PRDs and SDDs as input, and another input format it accepts is an Idea Slicer link.

13. **Use your own tools on every run.** Slicing is never a cold read of the input: the agent MUST work with (a) these rules, (b) the P-stack principles below as the decision criteria for every cut, and (c) the P-stack skills below as working tools — `/how` to understand an existing project before slicing it, `/technical-writing` and `/unslop` for all map and page prose, `multi-phase-plan` when the slice needs phasing (plan only — never execution). A run that produces output without applying them fails the run.

name: principle-experience-first

## Facts — verified truths about how this system behaves

1. An idea is a GitHub issue labeled `idea`; each added thought is a `thought`-labeled issue, auto-nested as a sub-issue by the robot.
2. The robot commits straight to `main`. Before every commit: `git stash -q; git pull -q --rebase origin main; git stash pop -q` — never push over the robot's head.
3. The robot auto-parks every new thought issue into the map's Unsorted lane. When that thought gets sliced, delete its park line.
4. A 422 "duplicate" when nesting a sub-issue means the robot already nested it — not an error.
5. The live page updates ~60–75s after the render run goes green. A curl grep on the live URL is the proof — a green run alone is not.
6. There are no unit tests. Verification = render run success + live-page grep for the feature string + a phone-width screenshot for any visual change.
7. `maps/<slug>.md` is the source of truth; the issue body is a mirror, re-synced with `gh issue edit <n> --body-file` after every publish.
8. Chat history is expendable by design. Any agent resumes cold with: `/ideaslicer — resume the <idea> idea (TR3-AI/idea-slicer issue #<n>)`.

## FAQs

- **How do I add to an idea?** Just talk. Each message becomes a `thought` issue and gets sliced into the map — no special format.
- **How do I continue in a new chat or with a different model?** Use the resume line in Fact 8. Everything needed lives in the repo and the issues.
- **Rebase conflict with the robot on a park line?** Keep the sliced version (your side), drop the robot's park line, `git rebase --continue`.
- **A sliced thought still sits in Unsorted on the live page?** That's the robot's stale park line — delete it from the map and republish.
- **Leftover `git stash` entry from the publish rhythm?** Inspect with `git stash show -p stash@{0}`; if its content is already committed and live, drop it.
- **Do issue comments re-render the page?** No — only issue body edits and new issues do.
